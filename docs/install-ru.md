# CoinsPay для Magento 2 — установка

Модуль принимает оплату криптовалютой через CoinsPay: покупатель выбирает монету и сеть на странице
оплаты CoinsPay, а заказ сам получает счёт-фактуру, когда платёж поступит. Деньги сразу уходят на
ваши кошельки.

Подходит для Magento Open Source и Adobe Commerce от 2.4.4 до 2.4.9. Нужен аккаунт CoinsPay с
магазином.

## Установка

Через Composer:

```bash
composer require coinspay/coinspay-magento
bin/magento module:enable CoinsPay_Payment
bin/magento setup:upgrade
bin/magento setup:di:compile            # в режиме production
bin/magento setup:static-content:deploy # в режиме production
bin/magento cache:flush
```

Без Composer: распакуйте `coinspay-magento.zip` в `app/code/CoinsPay/Payment` (в папке должен лежать
`registration.php`) и выполните те же команды, начиная с `module:enable`.

Модуль добавляет два статуса заказа: «Ожидает оплаты криптовалютой» (состояние Pending Payment) и
«Проверка криптоплатежа» (On Hold, а также Canceled для оплаты, пришедшей после отмены).

## Подключение

«Stores → Configuration → Sales → Payment Methods» → «CoinsPay: оплата криптовалютой». Ключ и
вебхук задаются для каждого сайта: переключите область вверху страницы на сайт, чтобы дать ему свой
магазин CoinsPay.

1. В кабинете CoinsPay откройте магазин.
2. В разделе «Ключи API» выпустите ключ с доступом **«Только счета»** и вставьте его в поле
   «Ключ API». Модулю больше не нужно, а вывести деньги таким ключом нельзя, даже если его прочитает
   кто-то из сотрудников с доступом к админке.
3. Поле «Адрес API» оставьте пустым: тогда модуль использует `https://coinspay.app/api/v1`.
4. В разделе «Вебхук» укажите адрес, который показывает модуль, сохраните и скопируйте секрет
   `whsec_…` в поле «Секрет вебхука».
5. Сохраните настройки, нажмите «Проверить подключение», затем в кабинете — «Отправить тестовое
   событие»: в модуле появится время, когда событие дошло.

Страны, которым виден способ оплаты, и ограничения суммы заказа — в группе «Checkout». Название
способа оплаты задаётся для каждой витрины: дайте русской витрине своё.

## Статусы заказа

Каждое событие счёта что-то делает с заказом, а группа «Статусы заказа» выбирает статус:

| Событие счёта | Что происходит | Статус по умолчанию |
|---|---|---|
| Заказ оформлен, ждём оплату | Pending Payment | Ожидает оплаты криптовалютой |
| Платёж в пути, оплачен частично | только комментарий | не меняется |
| Оплачен (в срок, после срока, с переплатой, отмечен вручную) | оплаченная счёт-фактура, Processing | Processing |
| Истёк без оплаты, счёт отменён | заказ отменяется, товар возвращается на склад | Canceled |
| Сумма не совпадает, оплачен отменённый заказ, тестовая оплата не от тестового покупателя, истёк или отменён с частичной оплатой | On Hold | Проверка криптоплатежа |

В списках есть и ваши собственные статусы того же состояния заказа. При каждом событии в историю
заказа добавляется комментарий с суммами, монетами и хешами транзакций; покупатель его не видит.

Если вы отмените заказ, модуль отменит его открытый счёт, и покупатель больше не сможет его оплатить.

## Тестовый режим

С ключом `cpk_test_` счета оплачиваются кнопкой на странице оплаты, монеты не переводятся. По
умолчанию способ оплаты тогда виден только тестовому покупателю: откройте магазин по ссылке
«Открыть магазин как тестовый покупатель» в настройках. Ссылка действует сутки в том браузере, где
вы её открыли. Тестовая оплата закрывает только заказы тестового покупателя.

## Если вебхуки не доходят

Модуль сам спрашивает CoinsPay об открытых счетах из cron Magento раз в 5 минут: cron Magento должен
работать. Кнопка «Обновить» на странице заказа и `bin/magento coinspay:sync` спрашивают сразу.

Адрес вебхука должен оставаться базовым адресом витрины, как его показывают настройки: Magento
перенаправляет другие имена хоста на него, а вебхуки перенаправлениям не следуют. В режиме
обслуживания Magento не принимает вебхуки — опрос наверстает после.

## Полезно знать

- Заказ оформляется до оплаты, как с PayPal: Magento сразу резервирует товар. Письмо о заказе уходит
  после оплаты (выключите «Отправлять письмо о заказе после оплаты», чтобы оно уходило сразу).
- Magento сама отменяет заказы, ожидающие оплаты, старше «Pending Payment Order Lifetime»
  («Sales → Sales → Orders Cron Settings»). Время на оплату в модуле должно быть короче: иначе
  страница настроек предупредит.
- Magento не открывает отменённый заказ заново: оплата, пришедшая после отмены, записывается в
  комментарий, а заказ получает «Проверка криптоплатежа» — решение за вами.
- Покупатель, закрывший страницу оплаты, может заплатить позже: в его кабинете на странице заказа есть
  кнопка «Перейти к оплате», пока счёт открыт.
- Счёт выставляется в валюте заказа, если CoinsPay её принимает, иначе — в базовой валюте.
- Журнал — `var/log/coinspay.log`. Ошибки записываются всегда, ключи и секреты — никогда.
